# GitHub 活动背景设计

**日期：** 2026-09-26

**目标：** 在首页宽屏横屏时间轴背后加入由 GitHub 每日贡献生成的活动场，不改变时间轴结构、滚动和内容；竖屏完全不展示活动背景。

## 数据

- 主数据源：GitHub GraphQL `contributionsCollection.contributionCalendar`。
- 当配置 `GH_ACTIVITY_TOKEN` 时使用该 token，可包含 `read:user` 对应的私有贡献聚合数。
- 未配置 token 时，为本地预览和 Action 兜底，读取 GitHub 公开贡献日历 HTML；只保存每日聚合计数，不保存私有仓库名或事件明细。
- 数据文件：`src/data/github-activity.json`，按日期保存 `0..n` 的贡献计数，并记录年份汇总与全局峰值。
- 刷新的数据没有变化时不重写文件。

## 时间对齐

- 时间轴仍是唯一视觉骨架，不增加年份节点。
- 相邻时间轴年份之间做分段归一化：
  - 有节点的年份映射到对应年份列。
  - 节点之间缺失的年份压缩到两列之间的背景带。
  - GitHub 数据开始前的年份保持空底。
- 横屏只显示活动场；竖屏不渲染活动场。

## 视觉

- SVG 活动场与时间轴列宽使用同一比例，节点位置对齐现有年份列。
- 以轴线为中界，上方为主活动场，下方为约 30%–40% 强度的趋势回声。
- 使用全局对数尺度、7 天平滑和分位数封顶，避免单日峰值或高频年份压扁其他年份。
- 背景为纯装饰层：`aria-hidden`、`pointer-events: none`，不增加交互和文本。

## 自动化

- 新增独立 GitHub Actions workflow，每周一 UTC 03:17 运行，也支持手动触发。
- workflow 在 `main` 上刷新数据；有变化时提交并推送回 `main`。
- 数据推送后通过 `workflow_dispatch` 触发现有 Pages workflow 重新部署。
- 拉取失败时保留仓库中已有数据，不阻断网站构建。
