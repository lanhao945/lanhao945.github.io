# Proposal

## Why

首页时间轴要讲的不是"我现在很强"，而是"相比过去的自己，这些年走了很远"。当前的三段式巡航读起来像传送带：光带被钉在视口正中、用户一碰就整体冻结并淡出，既没有"持续积累"的连续感，也没有终章；同时最有力的增长证据被压在背景里 —— 2020–2023 的贡献高位（日均 3.4–4.8 次）被压缩成约 32px 的锯齿，观众读不出"逐渐变多"的中间坡道。

因此本变更把"讲清楚成长"拆成两件事：让年份按证据占位（看得见的积累），让巡航按信息量逐站推进、并停在"现在"（读得懂的旅程）。

## What Changes

- 新增**逐站巡航**：以有卡片的年份为站，匀速滑行 + 每站停留；取消"光带钉在视口正中"的同速率滚动机制。
- 停留时长**自适应数据**：由该站条目数与距上一站的真实年份间隔算出（纯函数、确定性、可单测）。新增内容只增加总时长、不提高滑行速度；密集年自动久停、稀疏年自动短停，并有单站上限。
- **终章定格**：光带收敛到最新节点并停住，不再扫出屏幕或淡出；走过的年份留下暖色轨迹，越近越亮。
- **输入即交接**：滚轮 / 触摸 / 拖拽 / 键盘 / 焦点进入任一发生，立即停在构图完整的当前站；`prefers-reduced-motion` 下不启动巡航；全程无音效。
- **证据占位**：年份只要有卡片或贡献 > 0 就占一整列；两者都没有的连续年份才压缩为一段，并在轴上给出淡淡跨度提示。
- 活动场的 x 映射改为"按占位年份一对一段落"，消除压缩段把多年数据挤成锯齿的画法。

不在本版范围：纵向逐列浏览、音效、按访客去重的播放策略（v1 保持"每次打开播放一次"的现状）、按年份比例展开距离。

## Capabilities

### New Capabilities

- `timeline-tour`: 首页时间轴横屏巡航的节奏与终章 —— 逐站停留预算、匀速滑行、终章定格、轨迹、输入交接、无音效、reduced-motion 行为。
- `timeline-evidence-layout`: 年份占位与压缩规则、活动场 x 映射与采样、无卡片年份的跨度提示。

### Modified Capabilities

（无。仓库当前没有任何已建立的 capability。）

## Impact

- 代码：`src/utils/`（新增巡航计划纯函数与其单测）、`src/pages/index.astro`（推导占位年份）、`src/components/Timeline.astro`（布局占位与巡航运行时代码）、`src/utils/githubActivity.mjs`（x 映射与采样规则）。
- 可观察行为：横屏首页整段巡航在当前数据下由约 16s 变为约 22s（滑行速度默认保持 240px/s，站点停留合计约 9.6s）；轨道由 2784px 变为 4192px（8 个卡片年 + 4 个仅有贡献的年份 = 12 个占位，另有 1 个压缩段 2013–2015）。竖屏不展示活动场、也不巡航，行为不变；`prefers-reduced-motion` 下仍不自动滚动。
- 依赖：无新增运行时依赖。
- 需要协调的团队：无（单人仓库，无跨团队接口）。
- 回滚计划：改动集中在 1 个组件与 2 个工具文件，回滚即 revert 本次三个提交（① 巡航策略与单测 ② 运行时接入与终章 ③ 占位与映射），无数据迁移、无存储格式变化；巡航运行时代码在关闭时不影响手动滚动与滚轮接管，因此回滚后页面退化为"手动浏览 + 无巡航"的可用状态。
