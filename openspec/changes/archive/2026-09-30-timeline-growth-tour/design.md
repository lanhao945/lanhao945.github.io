# Design

## Context

- 横屏（`min-width: 900px` 且 landscape）时首页整屏展示时间轴：轨道是三行网格（上卡片 / 轴线 / 下卡片），年份列宽 `--tl-column: min(20rem, 72vw)`，列间距 `--tl-gap: 2rem`。
- 活动场是轨道内的绝对定位 SVG（`preserveAspectRatio="none"`），viewBox 由 `buildActivityField()` 生成：内部单位 `COLUMN_WIDTH=100`、`GAP_WIDTH=10`，与 CSS 的 20rem/2rem 同比例，因此内部 x 单位可以一一对到年份列。
- 占位现状：列只来自"有卡片的年份"（`groupTimelineByYear`）；跳过的年份在活动场里被压成 `GAP_WIDTH`（`buildActivitySegments` 用 `index * (COLUMN_WIDTH + GAP_WIDTH)`），并且 gap 段固定采样成 8 个 bin —— 多年数据显示被挤在约 32px 内。
- 巡航现状（`src/components/Timeline.astro`）：`FLOW_SPEED = 240px/s` 的 rAF 循环，用同一进度同时驱动 `scrollLeft` 与光带 `--tl-flow-x`；光带中心抵达视口正中后开始滚动，此后光带在屏幕上被钉住；结束时光带扫出右侧并淡出。滚轮/触摸/指针/键盘/焦点都会立即终止巡航。
- 约束：内容只会往后追加；活动数据每周由 GitHub Actions 刷新（年份覆盖可能变化）；`prefers-reduced-motion` 已有被尊重的先例；无新增依赖。

## Goals / Non-Goals

**Goals:**

- 巡航节奏完全由数据推导（站点集合、每站停留），不出现任何硬编码年份。
- 空间分配由"证据"决定，使 2020–2023 这类"无卡片但有贡献"的高位年份能被看见。
- 终章停在最新记录上（不扫出、不淡出），用户接管时停在一个完整站点上。

**Non-Goals:**

- 纵向逐列浏览、音效、按访客去重的播放策略、按年份比例展开距离。
- 不改动竖屏布局与竖屏下的信息展示。

## Decisions

### D1 站点 = 有卡片的年份，贡献年只作为滑行区间

只有卡片是可读内容；"只有贡献、没有卡片"的年份提供的是坡度而不是可停留的阅读对象，因此不停留。
*备选*：把贡献年也当站点 → 无内容可读、白拉长总时长，否。

### D2 节奏 = 匀速滑行 + 每站预算（纯函数）

停留时长由该站自身数据算出，滑行速度独立：

```
extra = min(items - 1, EXTRA_CAP)            // 条目多则久停，收益递减并封顶
quiet = gaps >= QUIET_GAP ? QUIET_BONUS : 0  // 真实年份间隔 >= 阈值时加一个静默拍
dwell = clamp(BASE + ITEM_STEP*extra + quiet, MIN, MAX)
```

初值：`BASE=0.9s`、`ITEM_STEP=0.45s`、`EXTRA_CAP=3`、`QUIET_GAP=4`、`QUIET_BONUS=0.4s`、`MIN=0.8s`、`MAX=2.6s`，终章额外 `+0.6s`；滑行速度沿用现有 `240px/s`。
*备选*：固定总时长再做归一化 → 内容变多时会加速，与"新增内容只加时长"冲突；纯 px/s 无停留 → 密集年读不出重点。两者都否。

### D3 占位规则（显式条件，由数据推导）

```
占位（整列） = 该年有卡片 || 该年贡献总数 > 0
压缩区间     = 连续年份中，两个条件都不满足的区间
```

*备选*：按年份比例展开 → 空年重新占地方（与现有偏好相反）；只压缩"无卡片"年份 → 2020–2023 高位被挤掉。都否。

### D4 活动场按占位年份一年一段

`buildActivitySegments(slotYears)` 的输入从"卡片年份"改为"占位年份"，每个占位年份仍占 `COLUMN_WIDTH`，压缩区间占 `GAP_WIDTH`；采样 bin 数继续由列宽推导（一年 ≈ 74 个 bin），因此不再出现"多年挤进一个窄段"。
*备选*：保留现状但把窄段采样改成按年被压缩的包络峰 → 仍要在 32px 内表达四年，否。

### D5 连续无卡片区间的跨度提示

无卡片年份没有年份标签，因此在轴上给出淡淡的年份范围提示（如 `2020–2023`）；当压缩区间宽度不足时退化为短标记（如 `…`），完整年份范围始终通过无障碍属性（`title` / `aria-label`）可获取。

### D6 终章与轨迹

巡航结束时把光带收敛到最新一站的节点位置并停住（不再扫出屏幕），页面停在该帧；已通过年份保留"已点亮"状态（`data-*` 状态 + CSS 变量渐变），不随时间衰减。用状态驱动而非逐元素动画，避免长列表的动画开销。

### D7 输入接管 = 吸附到最近站

停止时读取当前 `scrollLeft`，吸附到最近站点的列偏移（必要时用 ≤200ms 过渡），保证停在"构图完整"的一站而不是站间。
*备选*：冻结在当前位置 → 会出现"光带悬空 + 半张卡片"的构图，正是本次要修的体感。

### D8 reduced-motion / 竖屏 / 无音效

`prefers-reduced-motion: reduce` 下不启动巡航（保持现有静态光带）；竖屏/窄屏不巡航；不播放任何音频。

### D9 模块划分

- `src/utils/timelineTour.mjs`（新）：`planTour()` 纯函数与常量，客户端只消费其输出。
- `src/utils/githubActivity.mjs`（改）：新增占位推导 + 段映射语义调整。
- `src/components/Timeline.astro`（改）：渲染占位列/跨度提示；运行时改为按巡航计划推进。
- 确定性策略一律写成显式公式与常量，不经模型判断。

## Risks / Trade-offs

- [总时长从约 18s 增至约 24s] → 滑行速度与停留常量是两个独立旋钮；访客随时可接管；实现后按实测再定值。
- [轨道由 2784px 增至 4192px（12 个占位），横屏一屏可见列数减少] → 竖屏不受影响；压缩区间仍然存在；终章定格在最新列，首屏印象由活动场坡度承担。
- [数据刷新可能导致年份塌缩/展开，轨道宽度变化] → 已接受为"证据占位"的直接后果；如需固定，可改为自首个有记录年份起全部占位（后续独立变更）。
- [吸附接管可能产生一次位移] → 过渡限制在 200ms 内，或直接落位。
- [长间隔的滑行时间里没有停留] → 由静默拍在到站时补偿，间隔越久到站停留越久。

## Migration Plan

1. 提交 ①：新增 `planTour()` 纯函数与单测（不接入 UI）。
2. 提交 ②：`Timeline.astro` 接入逐站巡航、终章定格与轨迹；移除"钉在正中 + 扫出淡出"的旧机制。
3. 提交 ③：占位规则与活动场映射 + 测试（含跨度提示）。
- 无数据迁移、无存储格式变化；三个提交可独立 revert。回滚后页面退化为"手动滚动 + 无巡航"，竖屏与 reduced-motion 行为不受影响。

## Open Questions

- v1 保持"每次打开播放一次"（现状）；"仅首访播放"留给后续独立变更。
- 滑行速度与停留常量的最终取值：实现后实测微调，不影响规格与任务拆分。
